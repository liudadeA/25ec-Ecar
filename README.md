# 25ec-Ecar
25年电赛E题
这里主要做一点点经验分享，更多的讲一下我们的教训吧。

今年的题目说实话还算是比较简单的，按我们准备一个月的话应该是可以应付的，但是现在结果确实是做的很差，对此也是做一点反思。

第一个就是我们做了很多的无用功，比方说考虑代码的可读性，为了让其他人能看懂，能一起修改，花了时间加注释，分页。
另外就是两个人编辑同一份代码时思路没有统一，导致一个人写出来的被另一个人否掉，又重新构建，最后主要写这段代码的人又要花时间再重写，
这是一个很大的时间浪费。

第二个就是我们只准备了经验，但是对实际的代码的准备不足，正确的思路应该是将所有要用到的代码封装，后续只需要直接调用；挪用，而不是再重新写一边。
我们在准备的时候，把所有的代码写在了一起，导致挪用很困难，而且划分起来也很不清晰，这时候才是我们应该去把代码分页，整理的时候，而不是比赛时。

第三点我觉得也是我们失败的主要原因，调试的时间太少了，我们到比赛的最后一个下午才把车给组装起来，下地调试，此前只有分开的调试，
我们如果能更早的开始调试也许就能够发现树莓派有问题，发现激光只能打开一次，而不是比赛时才匆匆忙忙的找到问题而无法解决。

补充第四点我们做的时候有点‘好高骛远’明明简单的问题还没解决，就开始考虑下面的问题，这个也是应该避免的，应该一个问题一个问题的解决，
即使他们有相关性，但一道题得分就是一道题得分。

最后分享一点点经验，因为我是主要做的视觉，因此就说一些视觉方面的经验。
第一个就是设备问题，我们最开始用的k230，图像分辨率很小，识别的很勉强，而且帧率低，后面改成树莓派后图像识别率明显增高。
第二个就是滤波问题，在最开始发现识别错误，跟踪不及时的问题后我就开始考虑这个，最后采用了消去和卡尔曼滤波来预测，能够精准的跟踪目标。
